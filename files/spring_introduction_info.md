# Введение в Spring и Spring Boot

## Что такое Spring

**Spring Framework** представляет собой фреймворк для разработки Java-приложений: набор общих механизмов
и правил, на основе которых разработчик строит программу. Он помогает организовать взаимодействие объектов,
работу с базами данных, обработку веб-запросов и тестирование.

Spring имеет **модульную структуру**: в приложение подключают только необходимые части.
Например, Spring MVC отвечает за обработку веб-запросов. Помимо самого Framework, экосистема Spring
включает отдельные проекты: Spring Boot, Spring Data для доступа к данным и Spring Security для управления доступом.

### Как работает Spring

В основе Spring находится **IoC-контейнер**: механизм, который создаёт объекты, связывает их между собой
и управляет их жизненным циклом. Основной интерфейс контейнера называется `ApplicationContext`.
Объект, которым управляет контейнер, называется **бином (bean)**.

Разработчик указывает, какие объекты должны управляться Spring, с помощью конфигурации, в том числе аннотаций.
**Аннотации** являются специальными метками в Java-коде, которые фреймворк может обрабатывать.
На основе этой конфигурации контейнер создаёт бины и передаёт им необходимые зависимости.
**Зависимость объекта** здесь означает другой объект, необходимый ему для работы.

Такой подход основан на двух понятиях:

* **IoC (Inversion of Control, инверсия управления)**: управление созданием и связыванием объектов
  передаётся контейнеру.
* **DI (Dependency Injection, внедрение зависимостей)**: объект получает свои зависимости извне,
  например через конструктор. В Spring этот механизм реализует принцип IoC.

Отделение логики класса от создания его зависимостей упрощает замену компонентов и тестирование.
**Spring управляет только зарегистрированными бинами, остальные объекты можно создавать обычным способом.**
Подробнее об этих
понятиях: [контейнер и бины Spring](https://docs.spring.io/spring-framework/reference/core/beans/introduction.html).

### Что добавляет Spring Boot

**Spring Boot** представляет собой проект на основе Spring Framework, который упрощает настройку
и запуск приложений. В приложении с Boot продолжают работать те же бины, контейнер и внедрение зависимостей.

Основные возможности Spring Boot:

* **Стартеры**: наборы зависимостей для типовых задач, например разработки веб-приложения.
  Средства управления зависимостями Boot согласуют версии поддерживаемых библиотек.
* **Автоконфигурация**: настройка компонентов с учётом подключённых библиотек, объявленных бинов
  и параметров приложения. Настройки по умолчанию можно изменять.
* **Встроенный веб-сервер**: возможность запускать веб-приложение как самостоятельную Java-программу,
  без отдельной установки сервера.
* **Внешняя конфигурация**: хранение параметров в `application.properties`, `application.yml`,
  переменных окружения или аргументах запуска.

**Spring Framework предоставляет основные механизмы приложения, а Spring Boot упрощает их подключение,
настройку и запуск.** Логику самого приложения определяет разработчик. Принцип автоматической настройки описан
в [документации Spring Boot](https://docs.spring.io/spring-boot/3.5/reference/using/auto-configuration.html).

## Подключение Spring Boot к существующему Maven-проекту

Для подключения Spring Boot необходимо внести изменения в `pom.xml`: файл, который описывает зависимости
и настройки сборки Maven-проекта. Для ветки 3.5 необходимо использовать **JDK 17 или выше**
(комплект средств разработки на Java) и **Maven 3.6.3 или выше**.

### Родительский POM

В `pom.xml` необходимо добавить блок `<parent>` с `spring-boot-starter-parent` непосредственно внутри блока `<project>`.
Так задаётся родительский POM: описание проекта, от которого наследуются настройки Maven.
Он определяет версию Spring Boot, согласованные версии поддерживаемых библиотек и настройки Maven-плагинов.

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.5.5</version>
    <relativePath/>
</parent>
```

Пустой `<relativePath/>` отключает поиск родительского POM по относительному пути: Maven ищет его в репозиториях.
**Родительский POM управляет версиями, но сам по себе не подключает все библиотеки Spring.**
Нужные зависимости необходимо перечислить отдельно в блоке `<dependencies>`.
В проекте может быть только один `<parent>`.

### Зависимости для разработки веб-приложения

В раздел `<dependencies>` необходимо добавить стартер `spring-boot-starter-web`.
Он подключает следующие компоненты:

* **Spring MVC**: веб-фреймворк в составе Spring, который направляет HTTP-запросы к методам Java-классов
  и формирует ответы. HTTP является протоколом обмена запросами и ответами между клиентом и сервером.
* **Встроенный сервер веб-приложений [Apache Tomcat](https://tomcat.apache.org/)**: принимает HTTP-запросы
  и передаёт их приложению. Технически Tomcat является контейнером сервлетов: средой выполнения Java-компонентов,
  обрабатывающих веб-запросы. При таком подключении он запускается вместе с приложением, отдельная установка не требуется.
* **Библиотека [Jackson](https://github.com/FasterXML/jackson)**: преобразует Java-объекты в JSON
  (**сериализация**) и JSON в Java-объекты (**десериализация**). JSON является текстовым форматом
  обмена структурированными данными, который часто применяется в запросах и ответах веб-приложений.

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

Версия стартера не указана: она наследуется из `spring-boot-starter-parent`.
**Версию можно опускать только для зависимостей, которыми управляет конфигурация Maven-проекта.**

### Плагин для сборки и запуска

В блок `<plugins>`, расположенный внутри `<build>`, необходимо добавить Maven-плагин `spring-boot-maven-plugin`:

```xml
<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
            <!-- Версия наследуется из spring-boot-starter-parent -->
        </plugin>
    </plugins>
</build>
```

**Maven-плагин** является расширением системы сборки, которое выполняет определённые задачи.
Этот плагин позволяет запускать приложение через Maven и собирать исполняемый **JAR**:
Java-архив с кодом приложения и необходимыми зависимостями.
При использовании указанного родительского POM упаковка такого JAR уже предусмотрена настройками сборки.
**Зависимости предоставляют библиотеки для кода, а плагин выполняет действия при сборке и запуске.**

После изменения `pom.xml` необходимо обновить Maven-проект в **IDE**, чтобы она загрузила зависимости.

## Сборка и запуск Spring Boot-приложения через Maven

### Точка входа

Для запуска необходимо подготовить главный класс приложения с методом `main` и аннотацией `@SpringBootApplication`.
Метод `main` является **точкой входа**: с него начинается выполнение Java-программы.

```java
package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

В примере класс необходимо разместить в `src/main/java/com/example/demo/DemoApplication.java`.
В своём проекте необходимо использовать имя собственного пакета вместо `com.example.demo`.
**Главный класс следует размещать в корневом пакете приложения, а остальные компоненты в этом пакете
или его подпакетах**, чтобы Spring обнаружил их при сканировании.

Аннотация `@SpringBootApplication` объединяет три настройки:

* **`@SpringBootConfiguration`**: обозначает класс как источник конфигурации Spring,
  в котором можно дополнительно описывать бины.
* **`@ComponentScan`**: включает **сканирование компонентов** (component scan), то есть поиск классов
  с аннотацией `@Component` и производными от неё в пакете главного класса и его подпакетах.
  На основе найденных классов контейнер регистрирует определения бинов.
* **`@EnableAutoConfiguration`**: включает автоконфигурацию Spring Boot.

Отдельно добавлять эти три аннотации не требуется. Подробнее:
[назначение `@SpringBootApplication`](https://docs.spring.io/spring-boot/3.5/reference/using/using-the-springbootapplication-annotation.html).

Метод `SpringApplication.run` создаёт и настраивает IoC-контейнер, запускает создание необходимых бинов
и, при подключённом веб-стартере, встроенный сервер Tomcat. Аргумент `DemoApplication.class` указывает
класс конфигурации, а `args` передаёт параметры командной строки.

### Сборка проекта

Для сборки необходимо открыть терминал в каталоге с `pom.xml` и выполнить команду:

```bash
mvn clean package
```

**`clean`** удаляет результаты предыдущей сборки из каталога `target`.
**`package`** запускает этапы компиляции, выполнения тестов и упаковки приложения.
При настройках из предыдущего раздела Maven-плагин Spring Boot дополнительно выполняет **`repackage`**:
преобразует обычный JAR в исполняемый архив с зависимостями, включая встроенный сервер.

После успешной сборки в терминале появится `BUILD SUCCESS`, а в каталоге `target` будет создан JAR-файл.
По умолчанию его имя складывается из `artifactId` и `version`, заданных в `pom.xml`.
**Сборка создаёт архив приложения, но не запускает его для обработки запросов.**

### Запуск приложения

Для запуска необходимо выбрать один из двух способов.

**Через Maven-плагин** во время разработки необходимо выполнить:

```bash
mvn spring-boot:run
```

Предварительно собирать JAR командой `package` не требуется: плагин запускает приложение из скомпилированных
классов проекта.

**Через собранный JAR** необходимо выполнить:

```bash
java -jar target/app.jar
```

Вместо `app.jar` необходимо указать фактическое имя архива из `target`.
Приложение запускается как самостоятельный Java-процесс. Maven для такого запуска не требуется.
**После изменения исходного кода JAR необходимо собрать заново.**

В журнале запуска необходимо проверить появление сообщения `Started DemoApplication` и сообщения
о запуске Tomcat. По умолчанию сервер принимает запросы на порту **8080**.
Приложение продолжает работать до остановки, для остановки из терминала необходимо нажать `Ctrl+C`.

## Подробнее об инверсии управления (IoC) и внедрении зависимостей (DI)

### Передача зависимостей контейнеру

При использовании IoC необходимо описать, какие зависимости требуются компоненту, и предоставить контейнеру
их создание и передачу. Класс при этом сохраняет собственную логику работы, но освобождается от создания
объектов, которые ему необходимы.

Рассмотрим пример: класс `NotificationService` отвечает за отправку уведомлений,
а `OrderProcessor` использует его при обработке заказа. Если зависимость создаётся внутри класса,
код выглядит следующим образом:

```java
class OrderProcessor {
    private NotificationService notifier = new NotificationService();
}
```

Здесь `OrderProcessor` сам выбирает, как создать `NotificationService`.
Для передачи зависимости через Spring необходимо убрать создание объекта из поля и добавить параметр конструктора:

```java
import org.springframework.stereotype.Component;

@Component
class NotificationService {
}

@Component
class OrderProcessor {
    private final NotificationService notifier;

    public OrderProcessor(NotificationService notifier) {
        this.notifier = notifier;
    }
}
```

Аннотация **`@Component`** позволяет Spring обнаружить класс при сканировании и зарегистрировать его как компонент.
Для работы примера оба класса необходимо разместить в пакетах, охватываемых сканированием.

При создании `OrderProcessor` контейнер определяет тип параметра конструктора, находит подходящий бин
`NotificationService` и передаёт ссылку на него. `final` поле позволяет сохранить эту ссылку без последующего
переназначения.

### Способы внедрения зависимостей

Spring поддерживает три основных способа внедрения:

* **Через конструктор**. Зависимости передаются при создании объекта.
  Для обязательных зависимостей необходимо предпочитать этот способ, поскольку они явно перечислены
  в конструкторе и доступны с начала работы объекта.
* **Через сеттер**. Зависимость передаётся после создания объекта через метод установки значения поля.
  Такой способ подходит для необязательных зависимостей, если класс может работать без них.
* **Напрямую в поле**. Spring устанавливает значение поля, помеченного аннотацией `@Autowired`, после создания объекта.
  Этот способ скрывает зависимости из конструктора и затрудняет создание объекта в обычном тесте.

**`@Autowired`** указывает Spring на необходимость автоматического внедрения зависимости.
Её можно применять к конструкторам, сеттерам и полям. При этом обязательность зависимости и момент её передачи
необходимо учитывать отдельно. Например, `@Autowired` на сеттере по умолчанию делает зависимость обязательной.
Подробнее о правилах выбора зависимостей см.
[документацию `@Autowired`](https://docs.spring.io/spring-framework/reference/core/beans/annotation-config/autowired.html).

### Что необходимо учитывать

Для обязательной зависимости в примере должен существовать подходящий бин. Если он не зарегистрирован,
Spring не сможет создать `OrderProcessor`. Если подходящих бинов несколько, выбор необходимо уточнить.
Для этого можно использовать **`@Qualifier`**, указывающую нужного кандидата, или **`@Primary`**,
обозначающую предпочтительный бин.

**DI можно применять без Spring**, передавая объекты через конструктор вручную.
Это удобно в тестах, где вместо реальной зависимости можно передать тестовую реализацию с заданным поведением.

## Аннотация @Component, области видимости бинов, жизненный цикл

### Аннотация @Component и её специализации

Для автоматической регистрации компонента необходимо пометить его класс аннотацией **`@Component`**
и разместить в пакете, охватываемом сканированием. Spring обнаружит класс и зарегистрирует определение бина,
на основе которого контейнер создаст объект и внедрит его зависимости.

Кроме `@Component`, существуют специализированные аннотации, обозначающие роль класса:

* **`@Service`** необходимо использовать для классов сервисного слоя, содержащих бизнес-логику приложения.
* **`@Repository`** необходимо использовать для классов доступа к данным. Этот слой также называют **DAO**
  (Data Access Object). Он отвечает за чтение и сохранение данных, например в базе данных.
* **`@Controller`** необходимо использовать для контроллеров Spring MVC, обрабатывающих веб-запросы.

Эти аннотации являются специализациями `@Component`, поэтому дополнительно ставить `@Component` не требуется.
Для компонентов без более конкретной роли необходимо использовать саму `@Component`.
Различия не ограничиваются названием. Например, `@Repository` позволяет подключить преобразование исключений
библиотек доступа к данным в общую систему исключений Spring.
Подробнее см. [аннотации компонентов Spring](https://docs.spring.io/spring-framework/reference/core/beans/classpath-scanning.html).

### Области видимости бинов

**Область действия бина (scope)** определяет, когда создаётся новый экземпляр и где повторно используется существующий.
Она не связана с модификаторами доступа Java, такими как `private` и `public`.

По умолчанию действует область видимости **`singleton`**. Контейнер хранит один экземпляр для каждого определения бина
и передаёт его всем компонентам, которым требуется этот бин.
**Это один экземпляр на определение бина в контейнере, а не один объект класса во всей Java-программе.**

Другие области действия:

* **`prototype`** создаёт новый экземпляр при каждом запросе этого бина у контейнера.
* **`request`** предоставляет отдельный экземпляр на один HTTP-запрос.
* **`session`** предоставляет отдельный экземпляр на HTTP-сессию, объединяющую последовательные запросы клиента.
* **`application`** предоставляет один экземпляр на **`ServletContext`**, общий контекст веб-приложения
  в контейнере сервлетов.

Последние три области доступны в веб-контексте Spring. Для изменения области действия компонента необходимо
использовать аннотацию **`@Scope`** из пакета `org.springframework.context.annotation`, например `@Scope("prototype")`.

Подробнее см. [области действия бинов](https://docs.spring.io/spring-framework/reference/core/beans/factory-scopes.html).

## Конфигурация приложения через файл application.yml

### Файл настроек и формат YAML

Spring Boot позволяет хранить параметры приложения отдельно от Java-кода в файле `application.properties`
или `application.yml`. В нашем курсе необходимо использовать **YAML**, текстовый формат,
в котором вложенность настроек обозначается отступами.

Файл `application.yml` необходимо разместить в каталоге **`src/main/resources`**.
При запуске Spring Boot автоматически прочитает его и добавит свойства в **`Environment`**,
объединяющий настройки из разных источников.

В файле `application.yml` можно задавать как параметры используемых библиотек, так и вводить собственные, например:

```yml
greeting:
  text: "Hello Spring!"
```

Здесь `greeting` является группой настроек, а `text` вложенным ключом со строковым значением.
Полное имя свойства в Spring записывается через точку: **`greeting.text`**.

Ключи одного уровня необходимо выравнивать, а после двоеточия перед значением ставить пробел.
Неправильный отступ может изменить структуру настроек или привести к ошибке чтения YAML.

### Получение значения через @Value

Для чтения отдельного свойства необходимо использовать аннотацию **`@Value`**
из пакета `org.springframework.beans.factory.annotation`.
Следующее поле необходимо разместить внутри класса, объект которого управляется Spring:

```java
@Value("${greeting.text}")
private String greetingText;
```

Выражение **`${...}`** содержит имя свойства, значение которого Spring должен подставить.
При создании бина после вызова конструктора Spring присвоит полю `greetingText` строку `Hello Spring!`.
Поэтому читать внедряемое поле в конструкторе этого же класса нельзя.
Для получения настройки непосредственно в конструкторе аннотацию `@Value` необходимо поставить на его параметр.

**`@Value` получает значение из настроек Spring, а не читает YAML-файл напрямую.**
Свойство может быть переопределено другим источником, например аргументом командной строки.
Имя Java-поля не обязано совпадать с ключом свойства.

Если обязательное свойство отсутствует во всех источниках, создание бина завершится ошибкой.
Для бина, создаваемого при запуске, это помешает запуску приложения.
Если допустимо запасное значение, его необходимо указать после двоеточия:

```java
@Value("${greeting.text:Hello Spring!}")
private String greetingText;
```

Это альтернативный вариант того же поля. При отсутствии свойства `greeting.text` будет подставлена строка `Hello Spring!`.
Дополнительные кавычки вокруг значения внутри `${...}` не требуются.
Подробнее см. [использование `@Value`](https://docs.spring.io/spring-framework/reference/core/beans/annotation-config/value-annotations.html).

### Группы настроек и профили

Для связывания целой группы свойств с полями отдельного класса необходимо использовать
**`@ConfigurationProperties`**. Этот подход удобен при большом количестве связанных параметров,
а для одного значения в рассматриваемом примере достаточно `@Value`.
Подробнее см. [внешнюю конфигурацию Spring Boot](https://docs.spring.io/spring-boot/3.5/reference/features/external-config.html).

**Профиль** позволяет выбирать конфигурацию для определённых условий запуска.
Например, `dev` обычно обозначает разработку, а `prod` работу приложения с реальными пользователями.
Дополнительные настройки необходимо размещать в `application-{profile}.yml`, например `application-dev.yml`.
Такой файл загружается при активации соответствующего профиля, одного его наличия недостаточно.
Подробнее см. [профили Spring Boot](https://docs.spring.io/spring-boot/3.5/reference/features/profiles.html).

**После изменения `application.yml` необходимо перезапустить приложение.**
Если приложение запускается из JAR, после изменения файла в `src/main/resources` необходимо также
пересобрать архив, чтобы обновлённые настройки попали в него.

## Контроллеры и обработка GET-запросов

### Аннотации @Controller и @RestController

В Spring MVC **контроллер** является компонентом, методы которого обрабатывают HTTP-запросы.
Для объявления контроллера необходимо выбрать аннотацию в зависимости от способа формирования ответа:

* **`@Controller`** необходимо использовать при формировании веб-страниц через представления (view).
  Представление отвечает за отображение данных, например с помощью HTML-шаблона.
  Строка, возвращаемая методом такого контроллера без `@ResponseBody`, обычно обозначает имя представления.
* **`@RestController`** необходимо использовать, когда результат метода нужно передать непосредственно
  в **тело HTTP-ответа**, то есть в его содержимое. Это может быть обычный текст или данные в формате JSON.
  Такой контроллер подходит для **веб-API**, интерфейса, через который другие программы обращаются к приложению.

**`@RestController` объединяет `@Controller` и `@ResponseBody`.**
Аннотация `@ResponseBody` указывает, что возвращаемое значение необходимо записать в тело ответа.
Её также можно поставить над отдельным методом класса с `@Controller`.
Подробнее см. [объявление контроллеров](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller.html).

Объекты обоих видов контроллеров управляются Spring и могут получать зависимости через DI.
**`@RestController` не означает, что любой результат превращается в JSON.**
Spring выбирает подходящий преобразователь HTTP-сообщений, который записывает результат в ответ.
Строка в приведённом ниже примере передаётся как обычный текст, а Java-объекты могут преобразовываться
в JSON библиотекой Jackson.

### Контроллер для текстового ответа

**Эндпоинт (endpoint)** является точкой обращения к приложению, которую определяют путь и HTTP-метод.
В примере ниже реализован эндпоинт **`GET /hello`**.
HTTP-метод **GET** предназначен для получения данных.

```java
package com.example.demo;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HelloController {

    @Value("${greeting.text}")
    private String greetingText;

    @GetMapping("/hello")
    public String hello() {
        return greetingText;
    }
}
```

Свойство `greeting.text` задано `application.yml`, как показано в предыдущем разделе.
При создании контроллера Spring внедрит его значение в поле `greetingText`.

**`@GetMapping("/hello")`** связывает метод `hello()` с GET-запросами по пути `/hello`.
Имя Java-метода не определяет адрес запроса, адрес задаётся аннотацией.
Это специализированный вариант **`@RequestMapping`**, общей аннотации для настройки соответствия запросов методам.
Подробнее см. [сопоставление запросов](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-requestmapping.html).

При поступлении запроса Tomcat передаёт его Spring MVC, который выбирает и вызывает метод `hello()`.
Возвращённое значение `greetingText` записывается в тело ответа благодаря `@RestController`.
**Вызывать метод контроллера вручную для обработки HTTP-запроса не требуется.**

### Запуск и проверка запроса

После добавления контроллера необходимо запустить приложение.
Затем необходимо открыть в браузере адрес или отправить запрос из командной строки:

```text
http://localhost:8080/hello
```

Здесь **`localhost`** обозначает компьютер, на котором открыт браузер, **`8080`** является портом приложения,
а **`/hello`** путём эндпоинта. При открытии адреса браузер отправляет GET-запрос.

Для проверки из терминала можно использовать **curl**, утилиту отправки сетевых запросов:

```bash
curl -X GET http://localhost:8080/hello
```

Параметр `-X GET` явно задаёт HTTP-метод. В Windows PowerShell необходимо использовать `curl.exe` вместо `curl`.

При настройке `greeting.text` из предыдущего раздела ожидается ответ со статусом **`200 OK`**
и следующим телом:

```text
Hello Spring!
```

Для просмотра статуса и заголовков ответа в curl необходимо добавить параметр `-i`.
Если получен статус **`404 Not Found`**, необходимо проверить путь `/hello` и расположение класса контроллера
в сканируемом пакете. Если соединение не устанавливается, необходимо проверить запуск приложения и его порт.

## Создание проекта при помощи Spring Initializer

**[Spring Initializr](https://start.spring.io/)** является онлайн-сервисом для создания Spring Boot-проектов.
Он формирует структуру каталогов, файл сборки с выбранными зависимостями и главный класс с аннотацией
`@SpringBootApplication`.

### Создание и открытие проекта

На сайте необходимо указать параметры проекта:

* **Project**: `Maven`, **Language**: `Java`, **Packaging**: `Jar`.
* **Spring Boot**: стабильную версию без пометок `SNAPSHOT`, `M` или `RC`, обозначающих предварительные сборки.
* **Group**, **Artifact** и **Package name** можете указать любые.
* **Java**: версию установленного JDK из доступных для выбранной версии Spring Boot.

В блоке **Dependencies** необходимо нажать **Add Dependencies** и добавить **Spring Web**.
Она подключает Spring MVC, встроенный Tomcat и средства преобразования данных в JSON.
Так же для удобства можно подключить библиотеку **Lombok**.

После нажатия **Generate** необходимо распаковать скачанный ZIP-архив и открыть каталог с `pom.xml`
в IDE как Maven-проект. Затем необходимо выбрать JDK проекта и дождаться загрузки зависимостей.
Подробнее см. [создание проекта через Spring Initializr](https://spring.io/guides/gs/spring-boot/#scratch).

### Запуск проекта

Для запуска из IDE необходимо выполнить метод `main` сгенерированного главного класса.
При первом запуске необходим доступ к интернету.
Успешный запуск подтверждают сообщения `Started ...` и о запуске Tomcat на порту **8080**.
